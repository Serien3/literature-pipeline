# 论文解析树 Markdown 模板

本模板规定最终笔记的章节、核心标签和展开程度；分析过程与检查要求见 [SKILL.md](../SKILL.md)。花括号内是写作提示，成文时替换为实际分析；论文没有提供的信息使用“论文未交代（已检查：§…）”，而不是留空。

保留核心标签，标签下允许完整自然段，不要求逐句填表。跨章节使用稳定、具体的名称衔接；挑战、贡献和模块分别使用 `Technical challenge 1 — 具体名称`、`Contribution 1 — 具体名称`、`Pipeline module 1 — 具体名称`，其余分支使用章节号和描述性标题。

```markdown
# 《{论文标题}》阅读笔记

## 文献信息

| 项目     | 内容                                      |
| -------- | ----------------------------------------- |
| 标题     | {原始标题；需要时附中文译名}              |
| 作者     | {作者}                                    |
| 发表信息 | {会议/期刊、年份、版本或 DOI/arXiv}       |
| 阅读材料 | {文件或链接；版本日期；正文/附录覆盖范围} |
| 笔记日期 | {YYYY-MM-DD}                              |

> **一句话因果主线：** {任务 → 据本文叙述前人已推进到的边界 → 本文要推进的增量问题 → 核心洞见与方法学 → 主要证据 → 适用边界}
```

## 填写约束

- 五个一级分析章节全部保留；重复分支按论文实际数量增删。`文献信息` 不计入解析树章节。
- 同一概念跨章节出现时，按各节提示增加解释层次：Abstract 给结论，Introduction 依次建立知识边界、解释挑战和提出解题思路，Method 展开实现，Experiments 判断证据，Limitation 解释边界及成因。
- Background 和本文目标挑战的判定遵循 SKILL.md 的“重建知识边界并筛选本文问题”；完整保留思维对齐所需的问题演进，合并的是重复表述。
- 默认只使用当前论文及其附带材料。仅当用户明确要求核查前序工作或了解当前进展时才扩展外部材料，并将结果另列为“外部补充”。
- 定位采用当前材料最稳定的粒度，例如 `§3.2, Eq. (4)`、`p. 7, Fig. 3` 或 `Appendix B, Table 6`，放在相关段落或表格中。同一单元内连续事实可共用定位。
- 论文明确内容直接陈述；解释性推理使用“这意味着/可推断/一种机制解释是”；缺失信息使用“论文未交代/未单独验证”。
- 非方法型论文仍保留五章：把 `Technical challenge` 映射为研究缺口或识别难点，把 `pipeline/module` 映射为理论、论证或实证环节，把 `Experiments` 映射为论文采用的证据与稳健性检验；在 Overview 中说明适配方式。
